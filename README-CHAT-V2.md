# ARKAN Chat v2 — دليل النشر

## الفكرة
نظام محادثة دائم مرتبط بحساب العميل: محادثة واحدة لكل عميل مع ARKAN، تُنشأ تلقائيًا عند أول تسجيل دخول، وتبقى محفوظة عبر الأجهزة. RLS حقيقي في Supabase عبر JWT صادر من خادم OTP.

## مسار النشر (بالترتيب)

**1. قاعدة البيانات (5 دقائق)**
- Supabase → SQL Editor → نفّذ `001_chat_v2_migration.sql` كاملًا.
- ينشئ: `chat_users`, `conversations_v2`, `messages_v2`, `exchange_requests_v2` + جميع سياسات RLS + buckets (`chat-media` خاص، `avatars` عام) + Realtime.
- لا يلمس الجداول القديمة (`conversations`, `messages`) — النظام القديم يبقى يعمل حتى الانتقال الكامل.

**2. خادم الهوية (Railway — نفس خادم OTP المعلّق أصلًا)**
- `npm i jsonwebtoken uuid` داخل `server-otp/`.
- الصق محتوى `server-otp-patch.js` في `server.js`.
- أضف متغير بيئة `SUPABASE_JWT_SECRET` من: Supabase → Settings → API → JWT Secret.
- انشر. هذا هو نفس النشر المعلّق لديك — لا خادم إضافي.

**3. الواجهة**
- ارفع `chat-v2.html` و `settings.html` إلى المستودع.
- حدّث `OTP_URL` في أعلى سكربت `chat-v2.html` برابط Railway الفعلي.
- وجّه زر "تواصل مع ARKAN" في `app.html` إلى `chat-v2.html`.

**4. تفعيل حساب المالك (مرة واحدة)**
- سجّل دخولك بهاتفك 22236295050 وافتح `chat-v2.html` مرة واحدة (يُنشئ ملفك في `chat_users`).
- ثم في SQL Editor:
  ```sql
  update chat_users set role='owner' where phone='22236295050';
  ```
- أعد فتح الصفحة → تظهر لوحة المالك (قائمة كل المحادثات).

## مسار إنشاء المحادثة التلقائي
تسجيل دخول ناجح → `chat-v2.html` يقرأ الجلسة (`arkanClient`/`arkan_session`) → يطلب JWT من `/supabase-token` (يُتحقق عبر Firebase idToken أو PIN من Firestore) → `sub = uuidv5(الهاتف)` ثابت لكل جهاز → RPC `ensure_my_conversation()` تنشئ ملف المستخدم + محادثة واحدة (unique constraint يمنع التكرار) + رسالة ترحيب عند أول مرة فقط → العميل يدخل مباشرة إلى محادثته الدائمة.

## نظام التسجيل الصوتي
- ضغط مستمر على الميكروفون → تسجيل فوري + اهتزاز + عداد + موجة حية (AnalyserNode).
- سحب لليسار = إلغاء · سحب للأعلى = قفل (إيقاف مؤقت/استكمال/حذف/إرسال).
- معاينة قبل الإرسال: waveform حقيقية من مستويات الصوت، تشغيل/إيقاف، سحب للتقديم، سرعات 1x/1.5x/2x.
- صيغ حسب المتصفح: `audio/mp4` (Safari/iPhone) ثم `webm/opus` (Chrome/Android) مع فحص `isTypeSupported`.
- رفع عبر XHR بنسبة تقدم → bucket خاص → تشغيل عبر Signed URLs (ساعة واحدة، مع كاش).
- الرسالة optimistic (pending → confirmed)، وعند الفشل زر إعادة محاولة، وعند انقطاع الشبكة قائمة انتظار محلية تُرسل تلقائيًا عند عودة الاتصال.
- مشغّل واحد فقط في كل مرة، يستمر أثناء التمرير، ويحفظ موضع التوقف.

## الأمان
- RLS على كل الجداول: العميل يرى محادثته فقط؛ المالك/الطاقم يرون الكل (`is_staff()` security definer).
- `sender_id` مفروض = `auth.uid()` في سياسة الإدراج — لا يمكن تزويره من الواجهة.
- الوسائط في bucket خاص بسياسات storage على مستوى المسار `{conversation_id}/…` — لا روابط عامة دائمة.
- قبول/رفض العرض عبر RPC `respond_to_quote` فقط (لا صلاحية update عامة للعميل).
- سياسة `cu_update` تمنع المستخدم من رفع دوره ذاتيًا (`my_role()`).
- فحص نوع/حجم الملفات + تعقيم أسماء الملفات + منع `..` في المسارات + esc() ضد XSS.
- Rate limiting موجود أصلًا في خادم OTP ويُطبَّق على endpoint الهوية.

## اختبارات القبول (نفّذها بهذا الترتيب)
1. سجّل حساب عميل جديد → افتح chat-v2 → محادثة واحدة + رسالة ترحيب + أزرار سريعة.
2. سجّل دخول نفس الهاتف من جهاز آخر → نفس المحادثة بنفس الرسائل.
3. من settings.html ارفع صورة → تظهر فورًا في قائمة المالك (Realtime على chat_users).
4. سجّل صوتًا: اسحب لليسار (يُلغى)، ثم سجّل واسحب للأعلى (يُقفل)، أوقف/استكمل، عاين، غيّر السرعة، أرسل.
5. راقب: نسبة الرفع → علامة ✓ → ✓✓ → زرقاء عند القراءة.
6. أرسل صورة + PDF + إيصالًا (زر المرفقات) مع تعليق.
7. من المحادثة: "طلب بديلة" → املأ النموذج → تصل بطاقة للمالك.
8. المالك: "تقديم عرض السعر" → العميل يرى زري قبول/رفض → اقبل → المالك يحرّك الحالة عبر "إدارة العملية" حتى "مكتملة" — كل تغيير يظهر كرسالة حالة داخل المحادثة.
9. جرّب فتح محادثة عميل آخر بحساب عميل (عدّل الـ id يدويًا) → RLS يرفض.
10. فعّل وضع الطيران، أرسل رسالة → تظهر "فشل/معلّقة" → أعد الاتصال → تُرسل تلقائيًا.

## المشاكل القديمة التي حُلّت
| المشكلة | الحل |
|---|---|
| محادثات غير مرتبطة بالحساب (روابط `?c=`) | ربط دائم بـ user_id + JWT |
| تكرار المحادثات لنفس العميل | `unique(customer_id)` + RPC idempotent |
| "محادثة جديدة" رغم وجود رسائل | trigger يحدّث `last_preview` تلقائيًا |
| آخر رسالة لا تتحدث | trigger `on_message_insert` |
| اسم الملف الطويل يملأ القائمة | `smartName()` + أيقونة نوع في المعاينة |
| تسجيل صوتي بدائي بلا معاينة | نظام WhatsApp-grade كامل |
| لا حالة رفع/فشل | شريط تقدم + retry + قائمة انتظار |
| بطاقات قائمة ضخمة | تصميم مضغوط 46px avatar بأسلوب بنكي |
| لا صور شخصية | avatars bucket + settings.html |
| لا عدّاد غير مقروء | عدّادات في الجدول + trigger + تصفير عند القراءة |
| فقدان المحادثة عند تغيير الجهاز | الهوية = uuidv5(الهاتف) — ثابتة عبر الأجهزة |
| طلبات البديلة منفصلة عن المحادثة | `exchange_requests_v2` مرتبط بالمحادثة والعميل + بطاقات + سلسلة حالات |
